# T3 digital twin: flood-aware routing for Hanoi

This repository runs a flood digital twin for a rectangle of Hanoi. Every 15 minutes it checks a rain forecast. When enough rain is coming, it runs a 3Di flood simulation, turns the result into flood-depth maps, and loads the depth of every road piece into PostGIS. A routing service reads those depths and routes people around roads that are too deep for their vehicle.

## How it works

One Airflow DAG, `flood_mapping_full`, produces the flood data. Its tasks emit Airflow assets that start the `routing_adapter` and `flood_tiles` DAGs, and a failure in either one does not fail the core run. Two services read the data. `floodmap-backend` answers routing and depth questions from PostGIS, and the frontend draws flood-extent tiles from MinIO.

![Flowchart of one run of the simulation DAG and the vector tile, routing adapter, and history DAGs it starts. The simulation DAG checks the slot age and the forecast, runs the 3Di simulation, and extracts the depth grids. It then emits events that start the other DAGs.](fig01_system_flow.png)

| Stage            | Runs as                                              | What it does                                                                                                                                                                                                                                                                                  | Details                                                                                                                                                |
| ---------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Rain gate        | `0_check_forecast_rain` in `flood_mapping_full`  | Runs every 15 minutes (`*/15 * * * *`, `max_active_runs=2`). Asks Tomorrow.io for 2 hours of rain in 15-minute steps. If no step reaches `FLOOD_RAIN_THRESHOLD_MM_HR` (5 mm/h), skips every later task and the run succeeds. `FLOOD_TEST_RAIN_MM_HR` sets a fixed rain rate.          |                                                                                                                                                        |
| 3Di simulation   | `1_trigger_simulation`, `2_download_results`     | Creates a 3Di simulation from `TEMPLATE_ID` and `MODEL_ID` with the forecast rain. Hotstarts from the saved state for the run's slot, or the newest state up to two cycles older, and cold starts when none exists. Saves `results_3di.nc` per simulation.                              | [3Di orchestration](artifacts/docs/concepts/3di-simulation-orchestration.md)                                                                            |
| Depth rasters    | `3_calculate_depth`                                | Runs `threedidepth` per timestep with `gridadmin.h5` and `dem.tif`. Writes `depth_YYYYMMDD_HHMMSS.tif` in UTC+7. The earliest file names the run (`run_ts`).                                                                                                                        |                                                                                                                                                        |
| Raster tiles     | `9b_load_depth_raster`, PostGIS                    | Loads each depth raster as 256 by 256 pixel tiles in EPSG:4326 into `flood_depth_raster_tile`, and keeps the newest 8 runs. The backend reads the depth at a point and along a route from this table.                                                                                       |                                                                                                                                                        |
| Edge depth table | `9c_build_edge_depth_table` in `routing_adapter` | Samples each GraphHopper edge once per metre against the raster tiles and keeps the deepest sample. Writes the binary table that GraphHopper reads, and the wet edges to `edge_depth` and `edge_depth_run`.                                                                               | [Edge depth table format](artifacts/docs/concepts/edge-depth-table-format.md)                                                                           |
| Map tiles        | `9_build_flood_tiles` in `flood_tiles`           | Turns the first 2 depth rasters into depth-band polygons with GRASS GIS, cuts Mapbox vector tiles, and uploads them to the `flood-extent` MinIO bucket. The bucket is the only one with anonymous read.                                                                                     | [MinIO flood-extent pipeline](artifacts/docs/concepts/minio-flood-extent-pipeline.md)                                                                   |
| Routing          | `floodmap-backend`, port 8010                      | On `POST /route`, buffers the flooded edges, merges them into polygons, and groups them into depth bands relative to the vehicle's flood limit. Sends the bands to GraphHopper as `custom_model` and sets `ch.disable`. `GET /flood/areas` returns the same polygons for the overlay. | [GraphHopper backend](artifacts/docs/concepts/graphhopper-backend.md), [depth threshold model](artifacts/docs/concepts/routing-depth-threshold-model.md) |
| Route engine     | `graphhopper`                                      | Runs a pinned GraphHopper 12.0-SNAPSHOT build on a Hanoi extract. Every profile uses landmarks (LM), not contraction hierarchies.                                                                                                                                                             |                                                                                                                                                        |
| Frontend         | `flood-routing-frontend`                           | A fork of graphhopper-maps with the flood layer, legend, flood mode, and depth forecast chart. nginx proxies `/api/gh/` to the backend and `/flood-extent/` to MinIO.                                                                                                                     |                                                                                                                                                        |
| Depth history    | `flood_history`, TimescaleDB                       | Copies each run from `edge_depth` into the `depth_history` and `history_moment` hypertables.                                                                                                                                                                                            | [TimescaleDB schema](artifacts/docs/concepts/timescaledb-schema.md)                                                                                     |
