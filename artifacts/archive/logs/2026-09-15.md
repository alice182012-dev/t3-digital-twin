## Root cause found: real flood tiles look "fractioned" / patchy

User-reported symptom (screenshot): the tile overlay renders as scattered blue speckles across wide
areas rather than smooth/contiguous flood extent, matching a complaint already on record in
`artifacts/block.md` (2026-09-08, the same day this tile code was written): *"the tiles and the tif
doesnt look the same, the tiles doesnt encounter all of the tif data."*

Investigated against the real pipeline data (`grasshopper-routing/flood-timeseries/depth_20260809_202000_215000/depth_20260809_202000.tif`,
the "latest run" timestep visible in the screenshot, not today's newly-added test run):

- The raster is genuinely sparse at this timestep: 56,000,056 total 1m pixels, only 4,252 have any
  depth `> 0`, and only 1,424 (0.0025% of the raster) reach the 1cm display-band floor. Real,
  isolated wet cells scattered across a mostly-dry domain, not a broad contiguous flood — some of
  the "fractioned" look is the real data, not a bug.
- Separately, a real bug: every tile read reprojects (source CRS `EPSG:3405` differs from every
  tile's Web Mercator), and `rio-tiler`'s default reprojection resampling is nearest-neighbor,
  which keeps one arbitrary source pixel per output pixel — for cells this sparse, that drops most
  of them. Measured directly: a z14 tile (`13005/7213`) over a known-flooded area showed 3 pixels
  `>=1cm` under nearest-neighbor resampling vs 55 under `max` resampling, including the tile's
  single deepest cell (0.68m), which nearest-neighbor dropped entirely.
- `ensure_overviews()` (built lazily on first tile touch, `Resampling.average`) compounded this:
  GDAL's `build_overviews` doesn't support `Resampling.max` at all (rasterio raises
  `ResamplingAlgorithmError` if asked), and GDAL selects the nearest overview level before the
  reprojection warp runs — so an `average`-built overview would poison a `max`-resampled read
  downstream regardless of what the read step does. Averaging is also the wrong operation for
  safety-relevant data on its own terms: it dilutes real danger toward zero instead of preserving
  it.

Fix applied (commit `076b2c0`): removed `ensure_overviews()` entirely (GDAL can't build overviews
with `max`, and `average` actively hides real depth) and added `reproject_method="max"` to every
`Reader.tile()` call, so downsampling always keeps the deepest value in a pixel's footprint instead
of an arbitrary or averaged one. Verified in isolation (direct `render_tile()` call: 55 opaque
pixels for the z14 tile above, up from an implied ~3 before) and live through the rebuilt
`floodmap-backend` container via `curl` (same tile, same 55-pixel count, `200` status).
